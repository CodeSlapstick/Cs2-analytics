# parser/ — สคริปต์เสริม

สามสคริปต์ที่ใช้ตอนอยากได้ข้อมูลละเอียดกว่าที่ `main.py` ใช้ ทั้งหมดรันแยกกันได้
ไม่ต้องพึ่งกัน และไม่ต้องมีฐานข้อมูล

```
.dem ──[parse_demo.py]──> normalized JSON ──[map_zones.py]──> โมเดลโซน data/zones/*.json
                                           └[check_radar_calibration.py]──> ภาพตรวจพิกัด
```

> โปรเจกต์นี้เดิมมีเว็บแอป (Node + PGlite + React) ต่อท้าย pipeline นี้
> ตอนนี้หั่นออกแล้ว เหลือเฉพาะฝั่ง Python — ตัวหลักคือ `main.py` ที่รากโปรเจกต์

## ติดตั้ง

```bash
pip install -r parser/requirements.txt
```

## `parse_demo.py` — `.dem` → normalized JSON

```bash
python parser/parse_demo.py match.dem --summary       # ดูสรุปก่อน ไม่เขียนไฟล์
python parser/parse_demo.py match.dem -o data/matches/
python parser/parse_demo.py demo/*.dem -o data/matches/
```

| ตัวเลือก | ความหมาย |
|---|---|
| `-o, --out` | ไฟล์ปลายทาง หรือโฟลเดอร์ (ถ้าเป็นโฟลเดอร์จะตั้งชื่อไฟล์ตาม `external_id` ให้เอง) |
| `--tickrate` | tickrate ของเซิร์ฟเวอร์ ดีฟอลต์ **64** (Premier/matchmaking) — FACEIT บางเซิร์ฟเวอร์เป็น 128 |
| `--summary` | แสดงสรุปอย่างเดียว ใช้เช็กว่าไฟล์ parse ได้ก่อน |
| `--pretty` | จัดรูป JSON ให้อ่านง่าย (ไฟล์ใหญ่ขึ้น 2–3 เท่า ใช้ตอนดีบักเท่านั้น) |

**หลักการ: ไฟล์นี้ดึงข้อเท็จจริงดิบอย่างเดียว ไม่คำนวณสถิติ**
ใครฆ่าใคร tick ไหน พิกัดไหน / รอบไหนฝั่งไหนชนะ / ใครขว้างระเบิดอะไรกี่ลูก — แค่นั้น
ส่วน ADR, HS%, opening duel, trade, clutch ไปคิดตอนวิเคราะห์ที่เดียว เพราะถ้าปล่อยให้
สูตรอยู่สองที่ วันหนึ่งจะมีคนแก้ข้างเดียวแล้วตัวเลขสองทางไม่ตรงกันโดยไม่มีใครรู้

### เรื่องที่ต้องรู้ก่อนแก้ไฟล์นี้

**1. ชื่อคอลัมน์ของ awpy เปลี่ยนได้ระหว่างเวอร์ชัน**
โค้ดทุกจุดจึงเรียกผ่าน `col(df, "ชื่อแบบที่1", "ชื่อแบบที่2", …)` แทนการอ้างชื่อตรง ๆ
ถ้าอัปเกรด awpy แล้วบางส่วนหาย ให้เพิ่มชื่อใหม่เข้าไปในรายการ อย่าเปลี่ยนเป็นชื่อเดียวตายตัว

**2. `team_number` ยึดจากฝั่งในรอบแรก ไม่ใช่ฝั่งปัจจุบัน**
CS2 สลับฝั่งตอนครึ่งหลัง (MR12) ถ้ายึดฝั่งปัจจุบัน ผู้เล่นคนเดียวจะกลายเป็นคนละทีม
กลางแมตช์ ระบบทั้งระบบใช้ `2 = ทีมที่เริ่มฝั่ง T`, `3 = ทีมที่เริ่มฝั่ง CT`

**3. การหาว่า "ฝั่งที่ชนะ" คือทีมไหน ใช้ข้อมูลจริงของรอบนั้น**
ไม่ได้คำนวณจากกติกาสลับฝั่ง แต่ดูจาก tick ว่ารอบนั้นผู้เล่นของแต่ละทีมอยู่ฝั่งไหน
(กติกาสลับฝั่งใช้เป็นทางสำรองเมื่อไม่มี tick ของรอบนั้นเท่านั้น) เพราะ overtime
มีกติกาสลับฝั่งคนละแบบ และ demo ที่มีการ restart กลางแมตช์จะทำให้การนับรอบเพี้ยน

**4. `external_id` คำนวณจากเนื้อไฟล์ ไม่ใช่ชื่อไฟล์**
(SHA-1 ของ 2 MB แรก + ขนาดไฟล์) เปลี่ยนชื่อไฟล์แล้วแปลงใหม่จึงไม่กลายเป็นแมตช์ใหม่

**5. หนึ่งระเบิด = หนึ่ง event**
`awpy` คืนเส้นทางการเคลื่อนที่ของระเบิดเป็นหลายสิบแถวต่อลูก โค้ดเก็บเฉพาะแถวแรก
ของแต่ละ `entity_id` ถ้าลืมข้อนี้ตัวเลข "ยูทิลิตี้ที่ใช้" จะเฟ้อขึ้นเป็นสิบเท่า

### เทสต์

## `map_zones.py` — แบ่งแมพเป็นโซนด้วย unsupervised learning

```bash
python parser/map_zones.py de_dust2 --summary   # ดูผลก่อน ไม่เขียนไฟล์
python parser/map_zones.py de_dust2             # เขียน data/zones/de_dust2.json
python parser/map_zones.py de_dust2 --k 8       # บังคับจำนวนโซน
```

อ่านจาก **ไฟล์ normalized JSON** ที่ `parse_demo.py` สร้างไว้ (ดีฟอลต์ `data/matches/`)
ต่างจาก `main.py` ที่อ่าน `.dem` ตรง ๆ — ไฟล์นี้ใช้ KMeans + เลือกจำนวนโซนด้วย
silhouette ส่วน `main.py` ใช้ DBSCAN ที่ไม่ต้องบอกจำนวนกลุ่มล่วงหน้า

### เรื่องที่ต้องรู้ก่อนแก้ไฟล์นี้

**1. `random_state` ถูกตรึงไว้**
KMeans เริ่มจากจุดสุ่ม ถ้าไม่ตรึงจะได้โซนคนละชุดทุกครั้งที่รัน แล้วเทียบตัวเลข
ข้ามครั้งไม่ได้

**2. เลือก k จาก silhouette แต่ต้องผ่านเงื่อนไข "ทุกโซนมีจุดพอ" ก่อน**
silhouette สนใจแค่รูปทรงของกลุ่ม ไม่สนว่ากลุ่มนั้นมีข้อมูลพอจะคิดสถิติไหม
ถ้าปล่อยตามคะแนนล้วน ๆ ข้อมูลชุดแรก (128 จุด) จะเลือก k=9 แล้วเหลือโซนใช้ได้แค่ 3 โซน

**3. ชื่อโซนติดทีหลัง ไม่ได้ใช้ตอนจับกลุ่ม**
ตัวจับกลุ่มเห็นแค่พิกัด ถ้าเอาชื่อ callout ไปช่วยแบ่งกลุ่มก็ไม่ใช่ unsupervised แล้ว
และจะกลายเป็นแค่การจัดกลุ่มตามป้ายที่ Valve ตั้งไว้ ซึ่งไม่ได้บอกอะไรใหม่

**4. เทียบกับ baseline ทุกครั้ง**
`grid_baseline_silhouette` คือคะแนนของการตีกริดสี่เหลี่ยมที่มีจำนวนช่องใกล้เคียงกัน
มีไว้ตอบคำถาม "จะใช้ ML ทำไม ตีกริดเอาก็ได้" ถ้าไม่ชนะกริด ก็ควรใช้กริด

## `check_radar_calibration.py` — ตรวจค่าปรับเทียบภาพเรดาร์

```bash
python parser/check_radar_calibration.py de_dust2
```

เอาจุดตายจริงไปวาดทับภาพเรดาร์ แล้วดูว่าจุดที่ติดป้าย callout ตกตรงพื้นที่นั้นจริงไหม
ค่าปรับเทียบอ่านจาก `assets/radars.json` ซึ่งเป็นแหล่งความจริงแหล่งเดียวของทั้งโปรเจกต์
(ใช้โดย `main_full.py` ด้วย) เพิ่มแมพใหม่ก็แก้ที่ไฟล์นั้นที่เดียว

ค่าพวกนี้ผิดแล้วจับยาก เพราะภาพยังดูปกติ แค่จุดไปตกผิดที่ — เพิ่มแมพใหม่ทีไรควรรันตรวจทุกครั้ง

# CS2 Map Zone Analytics

หาว่า "จุดปะทะสำคัญของแมพอยู่ตรงไหน" จากไฟล์ demo ของ Counter-Strike 2 จริง
ด้วยสองวิธีที่คิดกันคนละแบบ แล้วเอาผลมาเทียบกัน
(SP-404 Senior Project · UTCC STECH)

```
ไฟล์ .dem  ──awpy──>  ตาราง events  ──┬── สูตรให้คะแนนบนกริด  (คนตั้งน้ำหนักเอง)
                                      └── DBSCAN หา hotspot   (ML หาเองจากความหนาแน่น)
                                              ↓
                                   เทียบกันว่าชี้ไปที่เดียวกันไหม
```

**ทำไมต้องมีสองวิธี** — สูตรให้คะแนนบนกริดอธิบายง่ายและตรวจได้ด้วยมือ แต่เส้นกริด
เป็นเส้นตายที่เราขีดเอง อาจผ่ากลางจุดปะทะจนจุดเดียวถูกหั่นไปคนละช่อง ส่วน DBSCAN
ไม่รู้จักกริดเลย มันจับกลุ่มจากความหนาแน่นของจุดจริง ขอบเขตโซนจึงวิ่งตามการเล่นจริง
และไม่ต้องบอกล่วงหน้าว่ามีกี่โซน ถ้าสองวิธีนี้ชี้ไปที่เดียวกัน = ผลน่าเชื่อถือ
เป็นการตรวจสอบไขว้ (cross-validation) แบบง่าย ๆ ว่าโซนที่ได้ไม่ได้มาจากสูตรที่เราตั้งเอง

## เริ่มใช้

```bash
pip install pandas numpy matplotlib scikit-learn awpy
python main.py
```

ได้ผลลัพธ์ในโฟลเดอร์ `output/` — ภาพ 2 ใบ (`zone_score_heatmap.png`,
`dbscan_cluster_map.png`) กับตาราง 2 ไฟล์ (`zone_scores.csv`, `hotspots.csv`)
พร้อมสรุปภาษาไทยในเทอร์มินัล

**ถ้าไม่มีไฟล์ `.dem`** โปรแกรมจะสลับไปใช้ข้อมูลจำลองให้เองอัตโนมัติ รันได้ทันที
ไม่ต้องตั้งค่าอะไร (ข้อมูลจำลองมี 4 hotspot ฝังไว้ ไว้ทดสอบว่า DBSCAN หาเจอจริงไหม)

## ปรับค่าเล่น

แก้ได้ที่บล็อก `CONFIG` บนหัวไฟล์ [main.py](main.py) แล้วรันใหม่ ไม่ต้องแตะส่วนอื่น

| ค่า | ความหมาย | ลองแล้วเกิดอะไร |
|---|---|---|
| `MAX_DEMOS` | parse กี่ไฟล์ | ไฟล์ละ 1–2 นาที ครั้งแรกเท่านั้น (มี cache) |
| `GRID_N` | แบ่งแมพกี่ช่อง | ยิ่งละเอียดยิ่งเห็นจุดชัด แต่แต่ละช่องมีข้อมูลน้อยลงจนสุ่มขึ้น |
| `W_KILL` `W_DAMAGE` `W_FIRE` | น้ำหนักในสูตรคะแนน | ดันน้ำหนักการยิงสูง ๆ แล้วโซนคะแนนสูงจะเลื่อนไปทางที่คนสเปรย์เยอะแทนที่จะเป็นที่คนตาย |
| `CLUSTER_ON` | เอาอีเวนต์ไหนเข้า DBSCAN | ใส่ `weapon_fire` ด้วยแล้ว hotspot จะกลืนกันเป็นก้อนใหญ่ (การยิงเกิดได้ทั่วแมพ) |
| `EPS` | รัศมีที่ถือว่าใกล้กัน | ใหญ่ไป = ทุกกลุ่มเชื่อมเป็นก้อนเดียว, เล็กไป = ทุกจุดกลายเป็น noise |
| `MIN_SAMPLES` | ต้องมีเพื่อนบ้านกี่จุด | ยิ่งสูงยิ่งเข้มงวด กลุ่มเล็ก ๆ จะถูกตีเป็น noise |

ตั้ง `EPS = None` ถ้าอยากให้โปรแกรมหา eps เองจากกราฟ k-distance
(ทุกครั้งที่รันจะพิมพ์ค่าที่กราฟแนะนำให้เทียบกับค่าที่ตั้งไว้อยู่แล้ว)
ตั้ง `USE_SYNTHETIC = True` ถ้าอยากใช้ข้อมูลจำลองทั้งที่มีไฟล์ `.dem` อยู่

## โครงโปรเจกต์

```
main.py           ตัวหลัก — 5 STEP ตั้งแต่โหลดข้อมูลถึงสรุปผล อ่านไล่จากบนลงล่างได้เลย
main_full.py      เวอร์ชันเต็มของ main.py — ผลเหมือนกัน แต่วาดทับภาพเรดาร์จริง
                  มี auto-tune eps และรับ argument จาก command line
assets/           ภาพเรดาร์ + ค่าปรับเทียบพิกัด (ใช้โดย main_full.py)
demo/             วางไฟล์ .dem ตรงนี้ (ไม่เข้า git)
output/           ผลลัพธ์ที่โปรแกรมสร้าง (ไม่เข้า git)
data/zones/       โมเดลโซนที่ fit ไว้แล้วจาก map_zones.py
parser/           สคริปต์เสริม ใช้ตอนอยากได้ข้อมูลละเอียดกว่าที่ main.py ใช้
docs/             เอกสารและสไลด์นำเสนอ
```

`main_full.py` ต้องลง Pillow เพิ่ม (`pip install pillow`) ถึงจะวาดพื้นหลังเรดาร์ได้
ถ้าไม่มีก็ยังรันได้ แค่ไม่มีภาพแมพรองข้างหลัง

## สคริปต์เสริมใน parser/

```bash
python parser/parse_demo.py match.dem --summary    # ดูว่า parse ได้ครบไหม
python parser/map_zones.py de_dust2 --summary      # แบ่งโซนด้วย KMeans + silhouette
python parser/check_radar_calibration.py de_dust2  # ตรวจว่าพิกัดตกตรงที่บนภาพแมพจริง
```
